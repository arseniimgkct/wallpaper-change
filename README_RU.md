## Коротко

DesktopOverlay ставит одну картинку — или один сплошной цвет — прямо поверх тех обоев, которые рисует сама Windows, и при этом остаётся строго **под** значками рабочего стола и панелью задач. Он ничего не меняет в `HKLM`, не нарушает групповую политику и оставляет машину ровно такой, какой её нашёл. Одно действие снимает оверлей и возвращает рабочий стол в исходное состояние.

Сделан для машин, где обои заблокированы доменной политикой, где *Параметры → Персонализация → Фон* серые, ничего не делает или молча откатывается. Это способ получить желаемый рабочий стол на компьютере, который вам не принадлежит.

<p align="center"><sub>Чистый Win32-interop. Без движка обоев, без redistributable, без установщика, без служб, без запланированных задач, без прав администратора.</sub></p>

## Зачем это нужно

На корпоративных машинах обои обычно заблокированы. Параметр групповой политики побеждает всё, что предлагает интерфейс: выбор фона отключён, предпросмотр показывает неправду, а любая попытка сменить картинку либо не делает ничего, либо через несколько секунд откатывается. Штатного способа обойти это из «Параметров» не существует.

DesktopOverlay идёт другим путём. Вместо борьбы с оболочкой он рисует дочернее окно **внутри окна рабочего стола**, на том слое, который находится между системными обоями и слоем иконок. Оболочка по-прежнему владеет настоящими обоями — оверлей просто находится над ними. Ничего не регистрируется, ничего не подделывается, ни одна политика не нарушается: картинка гость за столом самой оболочки.

## Что он умеет

| | |
|---|---|
| **Картинка** | Любой `JPG`, `JPEG`, `PNG`, `BMP`, `GIF`, `TIF` или `TIFF`. Масштабирование в режиме *cover*: полностью заполняет экран, сохраняет пропорции, лишнее обрезается. |
| **Сплошной цвет** | Шесть встроенных пресетов и полная палитра. Рендерится в полноразмерный битмап и обрабатывается точно так же, как картинка. |
| **Drag and Drop** | Перетащите файл в окно. Перетащите папку — из неё подхватится первый подходящий файл. |
| **Буфер обмена** | Кнопка **Буфер** или `Ctrl+V` берёт картинку прямо из буфера: изображение из браузера или Paint, скриншот, скопированный файл картинки, скопированный путь. Сразу ставится на рабочий стол. |
| **Под всем остальным** | Значки рабочего стола, рамки выделения, контекстные меню, панель задач, трей — всё это остаётся сверху и полностью живое. Оверлей не перехватывает фокус и не съедает ни одного клика. |
| **Переживает Проводник** | Сторожевой таймер заново прикрепляет поверхность в течение двух секунд после перезапуска Explorer, компоновка пересчитывается при смене разрешения, дисплея и DPI. |
| **Без мерцания** | Оболочка периодически перерисовывает свои обои поверх рабочего стола и стирает чужую поверхность, не присылая `WM_PAINT`. Цикл перерисовки раз в секунду, подкреплённый заранее масштабированным битмапом и единственным blit, держит картинку неподвижно при практически нулевой цене. |
| **Чистое снятие** | Прежде чем окно будет уничтожено, оно перерисовывает себя настоящими системными обоями — ни одного пикселя оверлея не остаётся на экране. |
| **Светлая и тёмная тема** | Одна кнопка переключает тему Windows на противоположную и перезапускает Проводник. Без диалогов и подтверждений: на кнопке всегда написано, в какую тему она переключит. |
| **Маленькая панель задач** | Одна кнопка уменьшает панель задач с 40 до 30 пикселей — тот самый параметр «Использовать небольшие кнопки на панели задач», на корпоративных машинах часто недоступный через «Параметры». Только Windows 10: в Windows 11 Microsoft параметр отключила. |
| **Автозапуск** | Необязателен. Возвращает последнюю картинку при входе в систему, вообще без окна. |
| **Откат** | Одно действие и письменный отчёт о том, что именно было восстановлено. |

## Требования

```
Операционная система   Windows 10 или Windows 11, x64
Среда выполнения       .NET 8 Desktop Runtime либо самостоятельная сборка из репозитория
Права                  Не требуются. Всё происходит в сессии текущего пользователя.
```

## Сборка

```powershell
git clone <адрес-репозитория>
cd DesktopOverlay
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

На выходе один самодостаточный исполняемый файл. Ничего ставить, ничего рядом не класть.

```powershell
# запуск
.\bin\Release\net8.0-windows\win-x64\publish\DesktopOverlay.exe
```

## Использование

1. Запустите `DesktopOverlay.exe`. Окно откроется по центру экрана.
2. Перетащите картинку в область предпросмотра, нажмите **Обзор**, выберите один из шести пресетов цвета, откройте полную палитру — либо нажмите **Буфер** / `Ctrl+V`, чтобы взять картинку из буфера обмена.
3. Нажмите **Установить обои**. Оверлей прикрепится к рабочему столу, в трее появится значок. (Вставка из буфера применяется сразу.)
4. Закрывайте окно — оно свернётся в трей, оверлей останется на месте.
5. Поставьте галочку **Запускать вместе с Windows**, если картинка должна пережить перезагрузку.

Кнопка темы называется **Сменить тему Windows на тёмную** или **на светлую** — в зависимости от текущей темы — и переключает её по нажатию.

Кнопка **Уменьшить панель задач** (или **Вернуть обычную панель задач**, если панель уже уменьшена) меняет высоту панели задач и перезапускает Проводник. Панель задач и открытые окна Проводника на секунду исчезают — это обязательное условие: оболочка читает размер панели только при старте, поэтому без перезапуска ничего не изменится. Оверлей переподнимается сам в течение двух секунд.

Закрытие окна никогда не завершает программу. Значок в трее — это якорь, и оверлей живёт ровно столько же, сколько живёт трей.

## Командная строка

| Аргумент | Действие |
|---|---|
| *(нет)* | Открывает окно утилиты. |
| `--set "<путь>"` | Открывает окно с уже выбранной картинкой и сразу применяет её. |
| `--apply "<путь>"` | Безоконный режим. Окно не показывается: поднимается оверлей с указанной картинкой, программа живёт в трее. Используется автозапуском. |
| `--revert` | Полный откат без открытия окна. |
| `--revert --light` | Полный откат и дополнительно восстановление светлой темы Windows. |

Именованный мьютекс гарантирует единственный экземпляр: повторный запуск тихо завершается, вместо того чтобы драться за рабочий стол с первым.

## Переменные окружения

| Переменная | Значение | Смысл |
|---|---|---|
| `OVERLAY_DEBUG_FILL` | `1` | Заливает поверхность маджентой. Отделяет проблемы с окном от проблем с отрисовкой. |
| `OVERLAY_NO_EX_TRANSPARENT` | `1` | Убирает `WS_EX_TRANSPARENT` и использует `WM_NCHITTEST → HTTRANSPARENT` для проскока кликов. Обходное решение для сборок, где DWM исключает прозрачный оверлей из композиции. |

## Как это работает

Рабочий стол — не одно окно. Это небольшая недокументированная иерархия окон, и проект нацелен именно на неё.

```
Progman
 ├── WorkerW          ← здесь живут системные обои оболочки
 ├── WorkerW
 │    └── SHELLDLL_DefView
 │         └── SysListView32    ← значки рабочего стола
 └── WorkerW          ← оверлей прикрепляется ЗДЕСЬ: под значками
```

Окно создаётся **как дочернее** от нижнего `WorkerW` с первого же вызова, с `WS_CHILD`, после чего уводится в самый низ Z-order. Оно никогда не показывается как top-level и потом не перевклеивается — этот путь молча ломается на некоторых сборках Проводника.

Четыре детали делают основную часть работы:

- **Правильный `WorkerW`.** Цель — не слой значков. Оверлей крепится к соседнему хосту *ниже* того, что содержит `SHELLDLL_DefView`. Слой значков прозрачен, поэтому картинка видна сквозь него, а значки вообще не требуют перерисовки. Крепление не к тому хосту — к тому, где живут значки, — помещает фон `SysListView32` поверх картинки. Это самая частая ошибка в самодельных оверлеях.
- **Только `BeginPaint`.** DWM композитит исключительно то, что нарисовано в контексте `WM_PAINT`. Рисование через `GetDC`, полученный после `EndPaint`, на экран не попадает вообще. Перед каждой перерисовкой вся поверхность инвалидируется, поэтому частичная область обновления не может оставить непокрашенных полос.
- **Активный цикл перерисовки.** Оболочка периодически перерисовывает свои обои поверх рабочего стола и стирает чужую поверхность, ни разу не прислал `WM_PAINT`. Картинка мигает и пропадает. Таймер раз в секунду рисует её заново — ровно так же, как живые обои подают непрерывные кадры.
- **Самозаряжающийся выход.** После `DestroyWindow` оболочка не перерисовывает область, которую занимало окно, и залипшие пиксели доживают до перезапуска Проводника. `RedrawWindow` по `Progman` и всем `WorkerW` не помогает. Поэтому поверхность перерисовывает себя настоящими системными обоями — прочитанными из `TranscodedWallpaper` либо из пути доменной политики — пока ещё жива, и только потом закрывается.

## Структура проекта

| Файл | Ответственность |
|---|---|
| `Program.cs` | Точка входа, мьютекс единственного экземпляра, разбор командной строки, безоконный трей-контекст, логирование, стабильная копия картинки в `%APPDATA%`. |
| `MainForm.cs` | Интерфейс: drag and drop, вставка из буфера, пресеты цветов, палитра, предпросмотр, применение, откат, автозапуск, переключение темы. |
| `ClipboardImage.cs` | Работа с буфером обмена: скопированная картинка, файл, папка или путь, с повторами, пока буфер занят другим приложением. |
| `OverlayEngine.cs` | Жизненный цикл оверлея: сторожевой таймер, таймер перерисовки, значок в трее, поиск хоста, повторное прикрепление после перезапуска Проводника, снятие. |
| `OverlayWindow.cs` | Сама поверхность: класс окна, прикрепление как `WS_CHILD`, Z-order, отрисовка в `WM_PAINT`, масштабирование *cover*, перерисовка системными обоями при закрытии. |
| `Native.cs` | Слой P/Invoke: `EnumWindows`, `FindWindowEx`, `CreateWindowEx`, `SetWindowPos`, `RedrawWindow`, а также поиск `WorkerW` и атрибут тёмного режима DWM. |
| `AutoStart.cs` | Автозапуск через `HKCU\...\CurrentVersion\Run` с полезной нагрузкой `--apply`. |
| `Reverter.cs` | Детерминированный откат: оверлей, автозапуск, переопределение обоев, размер панели задач, сохранённая картинка, тема. Там же `ThemeUtil`. |
| `TaskbarUtil.cs` | Размер кнопок панели задач: чтение и запись `TaskbarSmallIcons` в `HKCU\...\Explorer\Advanced`, восстановление исходного состояния, отказ на Windows 11. |
| `ShellUtil.cs` | Перезапуск Проводника — общий для темы и панели задач, потому что оба параметра читаются оболочкой только при старте. |

## Безопасность и откат

Утилита точно знает, что именно она меняет, и откатывает ровно это. Снимок реестра не делается никогда: он бесполезен, если значения уже изменены кем-то другим. Вместо снимка убирается исключительно собственный след утилиты:

```
поверхность оверлея     снимается через OverlayEngine.Remove()
запись автозапуска      удаляется из HKCU\...\CurrentVersion\Run
переопределение обоев   Wallpaper, WallpaperStyle, TileWallpaper в HKCU\Control Panel\Desktop
сохранённая картинка    wallpaper.* в %APPDATA%\DesktopOverlay
размер панели задач     TaskbarSmallIcons в HKCU\...\Explorer\Advanced
светлая тема            восстанавливается только по запросу
```

Доменный путь `\\сервер\шара` распознаётся как политика, а не как переопределение, и никогда не удаляется. Рабочий стол перерисовывается, а действие записывается в лог вместе с отчётом для человека.

## Логи и хранимые данные

```
%APPDATA%\DesktopOverlay\
 ├── overlay.log      журнал диагностики с дописыванием
 └── wallpaper.*      рабочая копия картинки для автозапуска
```

Рабочая копия существует по одной причине: чтобы оверлей продолжал работать после того, как исходный файл перемещён, переименован или вычищен из «Загрузок». Журнал ограничен собственной полезностью — первые восемь событий отрисовки записываются, затем шум прекращается.

## Диагностика

**Картинка не появляется.** Оверлей почти наверняка прикреплён не к тому `WorkerW`. Посмотрите хост в логе: там записываются хендл окна, хендл хоста и получившийся прямоугольник.

**Картинка мигает.** Не работает таймер перерисовки. Убедитесь, что в `overlay.log` есть периодические записи о перерисовке.

**Появился маджентовый прямоугольник.** В окружении выставлено `OVERLAY_DEBUG_FILL=1`. Уберите переменную: с поверхностью всё в порядке, заливка была диагностикой.

**После выхода из учётной записи или падения Проводника оверлей пропал.** Ничего делать не нужно: сторожевой таймер его вернёт. Если не вернул — переприкрепите вручную из меню трея.

**В «Параметрах» Windows фон выглядит неизменным.** Так и должно быть. Оверлей не трогает системные обои — в этом весь смысл проекта.

**Панель задач не изменилась.** Проверьте в `overlay.log` строку `Панель задач: запрошена …, подтверждена …`. Если там `нет` — запись в реестр запрещена политикой домена. Если подтверждена, а панель прежняя — Проводник не был перезапущен; сделайте это вручную через диспетчер задач. На Windows 11 кнопка неактивна и это ожидаемо: параметр отключён Microsoft.
