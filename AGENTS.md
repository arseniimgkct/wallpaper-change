# AGENTS.md

WinForms-утилита для Windows (`net8.0-windows`, x64). Ставит картинку или сплошной цвет на рабочий стол
поверх системных обоев, не меняя сами обои. Один проект, без тестов и без CI.

## Сборка и запуск

```powershell
dotnet build                                                    # достаточно: в корне один .csproj
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
.\bin\Release\net8.0-windows\win-x64\publish\DesktopOverlay.exe
```

- Соберётся только на Windows. Код насквозь Win32 P/Invoke и WinForms; на Linux/macOS сборка невозможна.
- Флаги `-r win-x64 --self-contained` и `SingleFile` уже зашиты в `.csproj`, поэтому
  `dotnet publish DesktopOverlay.csproj -c Release` тоже даёт рабочий EXE (~63 МБ).
- Сборочные выходы `bin/`, `obj/` и все `*.exe`/`*.dll` в `.gitignore` — не коммитить.
- Файла решения нет, и `.gitignore` содержит `*.sln`, так что создавать `.sln` бессмысленно.

## Проверка изменений

- Тестов, линтеров и `.editorconfig` в репозитории нет. Единственная проверка — `dotnet build`
  (проходит с 0 предупреждений; `Nullable` включён, так что новые CS8xxx-предупреждения — регрессия).
- Форма `.Designer.cs`/`.resx` не используется: весь UI собирается в коде в `MainForm.cs`.
  WinForms-дизайнер Visual Studio здесь неприменим, правьте конструктор руками.
- Приложение — `WinExe` без консоли: stdout не используется, вся диагностика пишется в
  `%APPDATA%\DesktopOverlay\overlay.log`. Не ждите вывода в терминале.

## Побочные эффекты — главная осторожность

Запуск утилиты меняет систему: переопределяет `Wallpaper` в `HKCU\Control Panel\Desktop`,
переключает тему, размер панели задач, автозапуск и **перезапускает Проводник**
(`ShellUtil.RestartExplorer` — закрывает и поднимает `explorer.exe`).

- Не запускайте приложение и `--revert` ради «проверки, что собралось». Откат трогает те же
  ветки реестра, что и обычная работа.
- `Reverter.RevertAll` — единая точка отката. Новые обратимые действия обязаны попадать в неё
  и в отчёт для пользователя, иначе после сбоя систему не вернуть.
- Доменный путь `\\сервер\шара` в `RevertAll` распознаётся как политика и не удаляется
  намеренно. Не «чините» это условие.
- После записи в реестр (тема, размер панели) нужен перезапуск Проводника — оболочка читает
  эти значения только при старте.

## Мгновенный экземпляр и режимы запуска

- Мьютекс `Local\DesktopOverlay.SingleInstance`: второй экземпляр молча завершается. Если
  `dotnet run` «ничего не делает» — скорее всего, приложение уже запущено.
- Точки входа в `Program.cs` (там же константы, лог, `TrayContext`):
  - без аргументов — окно утилиты;
  - `--set "<путь>"` — окно с предустановленной картинкой и немедленным применением;
  - `--apply "<путь>"` — автозапуск: только оверлей и трей, без окна (`TrayContext`);
  - `--revert [--light]` — откат без окна. Флага `--help` нет.
- Автозапуск пишет в `HKCU\...\CurrentVersion\Run` вызов именно с `--apply`.

## Структура

- `Program.cs` — не только точка входа: константы (`ImageExtensions`, `DataDir`), лог,
  `LoadStableCopy`, класс `TrayContext`.
- `OverlayEngine.cs` — жизненный цикл оверлея: watchdog (2 с), таймер перерисовки (1 с),
  значок в трее, поиск хоста, переприкрепление после рестарта Проводника.
- `OverlayWindow.cs` — само окно: класс, прикрепление `WS_CHILD` к нужному `WorkerW`, Z-order,
  `WM_PAINT`, масштабирование *cover*, «чистая» перерисовка системными обоями при снятии.
- `Native.cs` — весь P/Invoke. Новые вызовы Win32 добавляйте сюда.
- `ThemeUtil` живёт внутри `Reverter.cs`, а не в отдельном файле.

## Диагностика через переменные окружения

- `OVERLAY_DEBUG_FILL=1` — заливка поверхности маджентовым; проблема с DWM выглядит как маджентовый прямоугольник.
- `OVERLAY_NO_EX_TRANSPARENT=1` — снимает `WS_EX_TRANSPARENT` и `WM_NCHITTEST → HTTRANSPARENT`,
  чтобы оверлей начал ловить клики. Нужно, когда разбираетесь с перекрытием рабочего стола.
- В лог пишутся хендл окна, хендл хоста и получившийся прямоугольник: почти все проблемы
  «картинка не появилась» решаются чтением `overlay.log`.
